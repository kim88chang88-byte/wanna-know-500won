# 구조 및 결정 사항

## 확정된 결정
| 항목 | 선택 |
|---|---|
| 형태 | 모바일 웹 |
| 프레임워크 | Next.js (App Router) + TypeScript |
| 사주 풀이 | 만세력 계산 + AI 풀이(Claude API) |
| 만세력 라이브러리 | `lunar-typescript` (연주·월주, 음력 변환에만 사용) |

## 요청 흐름
1. 사용자가 `BirthForm`에 생년월일시 입력 (양력, 또는 음력 연·월·일 + 윤달 체크)
2. `POST /api/reading` 호출
3. (예정) 결제 확인
4. `calculateSaju` 로 사주 명식 계산
5. `interpretSaju` 로 명식 기반 풀이 생성 (구현 전에는 명식만 반환)
6. 결과를 화면에 표시

## 만세력 계산 규칙 (calculate.ts)
| 기둥 | 계산 방식 |
|---|---|
| 연주 | 입춘이 되는 **정확한 순간** 기준 (lunar-typescript) |
| 월주 | 12절기(입춘, 경칩, 청명 …)가 되는 **정확한 순간** 기준 (lunar-typescript) |
| 일주 | 율리우스 일수로 직접 계산 (`ganzhi.ts`) |
| 시주 | 일간 + 시각으로 직접 계산 (오서둔, `ganzhi.ts`) |

### 시간 처리
- 입력 시각은 **한국 표준시(KST) 시계 기준**입니다.
- lunar-typescript 는 절기 시각을 중국 표준시(UTC+8)로 비교하므로, 연주·월주를 구할 때만 입력 시각에서 **1시간을 뺀 값**을 넘깁니다. (한국이 1시간 빠름. 빼먹으면 절기 전후 1시간 안에 태어난 사람의 연주·월주가 틀립니다)
- **야자시(23:00~23:59)**: 기본은 일주는 당일, 시주 천간만 다음 날 일간 기준(`lateZiHour: "sameDay"`). 조자시 방식은 `"nextDay"`.
- **진태양시 보정**: 기본은 보정 없음. `timeOffsetMinutes` 로 일주·시주에만 적용 (서울은 대략 -32분). 절기 판정은 실제 순간 기준이라 보정과 무관합니다.
- **태어난 시각을 모를 때**: 시주는 `null`. 그날 절기가 바뀌면 `uncertainPillars` 에 연/월이 들어갑니다.

### 알려진 한계
- 지원 범위는 **1900~2100년**.
- 음력 변환은 **중국 음력 기준**(lunar-typescript)입니다. 한국 천문연구원(KASI) 음력과 드물게 다른 해가 있을 수 있습니다. 음력 입력을 중요하게 다룰 거라면 KASI 데이터와 대조하는 테스트를 추가하세요.
- 과거 한국 표준시 변동(1954~1961 UTC+8:30, 서머타임)은 자동 보정하지 않고 `warnings` 안내만 붙입니다.
